# Independent review: OAMP e46aa19

## Summary

Overall risk: **high** for a globally loaded adaptive selector, primarily because shared eligibility is not isolated by process policy and catalog presence is mistaken for route availability.
The empty-candidate path also leaves the discard-endpoint marker selected, contrary to the documented invariant.
Reviewed README, design v1.3, compatibility notes, all `src/` and `test/` modules; all 41 existing tests pass (200 assertions).
Findings below are verified by source inspection; failure scenarios are code traces, not live OpenCode reproductions. No external APIs, credentials, or production databases were accessed.
Review performed on GCE, 2026-11-10; commit `e46aa19b1f8f017016b0169e01e94349ab40fea6`; worktree clean before and after review.

| C04 | medium | `src/index.ts:32`; `src/log.ts:9` | Logger initialization can reject plugin initialization before the intended storage failure guard. | Configure a storage path beneath an inaccessible/non-directory parent: `initLog()` calls `mkdirSync()` outside the `openDb` try/catch and rejects `OampPlugin`, instead of returning `{}` as intended for storage failures. | C05 | medium | `src/selector/hook.ts:46`; `src/selector/select.ts:34`; `src/selector/hook.ts:83` | The session limit is bypassed by inherited child routes and is not atomically reserved across processes. | An auto parent on `exaone/*` creates a child. | C06 | medium | `src/telemetry/usage-import.ts:105` | History upserts overwrite more accurate live E2E/TPS/request-start timestamps. | A live row measures headers at 1000, first token at 3100, completion at 5100 and 150 output tokens: E2E=4100 ms, TPS=75. | C07 | medium | `src/telemetry/live.ts:105`; `src/scoring/routes.ts:53` | Health orders completed outcomes by request start, but retry failures by failure time; cooldowns also age from request start. | Request starts at t=0, emits retry failure at t=10s, succeeds at t=20s. Conversely, a request that errors after 96 seconds without a retry row can have its 60-second cooldown already expired when the error is first observed. | Store a separate outcome/completion timestamp and order health transitions/cooldown deadlines by that field. | C08 | medium | `src/selector/hook.ts:26`; `src/telemetry/live.ts:54` | Cross-process failures do not invalidate another process's cached health decisions. | A caches healthy route X. A receives another turn within 60 seconds and reuses the cached healthy verdict, selecting X despite the shared DB failure. | Advance a shared metrics/health generation on relevant writes and compare it before using cached scores, or read current health separately at final selection time. Account for cooldown expiry as well as new failures. |
| C09 | medium | `src/index.ts:97` | Usage updates do not trigger performance recomputation, although updates are the normal path once live telemetry exists. | Live telemetry has already inserted each message without tool counters. | C10 | medium | `src/index.ts:89` | Refresh and usage import are a one-shot startup callback, not periodic maintenance. | A long-running TUI stays open beyond six hours or a day: no code schedules another provider refresh, benchmark refresh, or usage import. `providerModelsHours`/`benchmarkHours` only gate calls when some process starts or a CLI command runs; tool-quality evidence from later turns is not imported in that process. | Schedule bounded background maintenance with existing cross-process leases and cleanup, or trigger due checks from suitable nonblocking lifecycle points. Document that catalog injection itself takes effect on the next host catalog load. |
| C11 | medium | `src/telemetry/usage-import.ts:128`; `src/scoring/routes.ts:60` | Unfinished assistant messages are imported as successful availability outcomes. | A worker starts while other sessions have pending requests. Each row without `error`, even without `time.completed`/finish, is inserted as `outcome='ok'`; route availability counts it and `healthOf` can let this newer fake success clear an earlier cooldown. - Inspected credential resolution and fetch code without opening credential files. Provider/benchmark fetches use fixed HTTPS endpoints and refuse redirects; provider failures avoid response bodies. Usage import opens its source SQLite DB with `{ readonly: true }` and hashes message/session IDs. No verified plaintext credential disclosure was found in the reviewed normal paths; this is not a production secret audit.
- No live plugin loading, host calls, external API calls, production DB reads, package installs, or git mutations were performed. New targeted regression tests were not written under the read-only constraints; table scenarios are supported by source-level control/data flow, while only the existing suite was executed.

## Test gaps

- Two independent DB connections/processes with different paid/deny/provider policies; disconnected providers; actual host catalog intersection.
- Empty catalog and DB/initialization failures through the plugin hook wrapper, asserting that no marker reaches a provider call.
- Parent plus multiple children and simultaneous first-turn reservations on a `maxSessions:1` route; cleanup and expiry of reservations.
- Live-then-import and import-then-live merges, unfinished messages, retry-to-success ordering, slow final failures, and cross-process health invalidation.
- Update-only usage imports and maintenance timers with a fake clock; refresh during long-running TUI operation.
- Manual selection of the same real route currently chosen by auto: current equality heuristic cannot distinguish explicit pinning from implicit continuation. Also test a changing best challenger during the hold period, input/model defaults, and child-parent model divergence.
- Numerical option validation (nonfinite/negative weights and zero denominators), benchmark effort variants, and per-bucket latency behavior rather than only default-weight happy paths.
